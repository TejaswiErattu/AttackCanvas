## Part 1. Security review

No finding reaches High. The boundary is well built: content is wrapped and tag-escaped (context.ts:98-115), facts go through `oneLine`, the MCP choke point enforces allowlist/timeout/size (base.ts:208-236), redaction runs before Semgrep and before every model call, logs are secret-checked, the routes validate with Zod and echo nothing. The Mediums below are defence-in-depth; none is required by the prompt ("High or above"), so they are listed as **optional** fixes at the end.

| file:line | Issue | Severity | Fix |
|---|---|---|---|
| `src/server/mcp/githubClient.ts:431-441` (`normalizeEntry`) and `src/server/mcp/semgrepClient.ts:422` | Tree entry paths are accepted verbatim from the GitHub MCP/REST response and forwarded as `code_files[].path` to the Semgrep MCP server, which materialises them on disk. Git forbids `..`/absolute components, so exploitation needs a compromised server response, but nothing on our side rejects `../x`, `/etc/x`, `\`, or NUL. | Medium | In `normalizeEntry`, drop entries whose path has a `..` or `.` segment, starts with `/`, or contains `\\`/`\0`. |
| `src/server/mcp/base.ts:140-174` (`extractResources`) | Each resource block is capped at `maxBytes` individually; the total across blocks is unbounded, so a response with many 1 MiB resources is fully assembled. `extractText` caps the running total correctly. | Medium | Track a running total in `extractResources` and throw `REPO_TOO_LARGE` when it exceeds `maxBytes`. |
| `src/app/api/analyze/route.ts:101` and `[id]/answers/route.ts:67` | `request.json()` parses an unbounded body before Zod sees it; App Router handlers have no default body limit. A multi-MB JSON body pins the event loop. | Medium | Reject when `content-length` > 8 KB (or read the text with a cap) before parsing. |
| `src/server/scanners/osv.ts:828-847` | The number of `/v1/vulns/{id}` detail fetches is unbounded (`wanted` = every distinct advisory id). A manifest with thousands of dependencies can trigger thousands of sequential-ish (5-wide) fetches at 10 s timeout each, well past the 10-minute pipeline deadline. Also Part 2 case 12. | Medium | Cap `wanted` (e.g. 400 ids, highest-count first) and add a limitation line when cut. |
| `src/server/http/rateLimit.ts:99-103` | `clientKey` trusts the rightmost `X-Forwarded-For` hop. Correct behind a proxy that appends (Render does), but a direct `next start` exposure lets the client choose its bucket. Documented in the file. | Medium (deployment-dependent) | Keep; add a startup warning when `TRUST_PROXY` is unset, or read `x-real-ip` set by Render as the primary key. |
| `src/server/ingest/loader.ts:285-304` | All `MAX_FILES` (300) candidates are fetched before the 2 MiB total budget is applied (by design, since tree sizes can be wrong). Worst case 300 × 1 MiB (MCP cap) downloaded per analysis. Also Part 2 case 3. | Medium | Use the tree size as a pre-filter: stop selecting once the claimed cumulative size exceeds 2 × `MAX_TOTAL_BYTES`; keep the post-fetch enforcement. |
| `src/server/ingest/loader.ts:297-302` | A non-lockfile whose tree size was missing and which turns out to be over the 1 MiB cap makes `getFileContent` throw `REPO_TOO_LARGE`, which fails the whole analysis instead of skipping the file. Also Part 2 case 4. | Low | Treat `REPO_TOO_LARGE` from a single file fetch as "ignored" for every file, not only lockfiles. |
| `src/server/security/redactor.ts:337-352` | `generic_secret` needs a credential keyword in the key. An opaque bearer token in a header literal (`headers: { Authorization: "Bearer 3f9a…" }`) or a hex/base64 secret assigned with `:` is not caught unless vendor-shaped or high-entropy with `=`. Known design trade-off. | Low | Add an `authorization`/`bearer` key rule: `Authorization\s*:\s*['"]Bearer\s+(?<secret>\S{16,})`. |
| `src/server/analysis/context.ts:102-106` (`escapeAttribute`) | `>` is not escaped in the path attribute, so a path like `a">junk` renders as `<repo_file path="a&quot;>junk">`. Cannot close or open a block (`escapeRepoFileTags` runs first; the wrapper regex needs an exact line), so no injection, only a malformed-looking tag. | Low | Escape `<` and `>` in `escapeAttribute`. |
| `src/server/ingest/urlParser.ts:94-97` | `.git` is stripped from the end of the whole pathname, so `/tree/release.git` loses its ref suffix. Cosmetic. | Low | Strip `.git` only from `parts[1]`. |
| `src/server/security/redactor.ts:646-658` (`toEvidence`) | Not wired: no caller exists outside the redactor, so a committed credential is redacted but never surfaced as evidence or a threat. Also Part 2 case 6. | Low (product gap, not a leak) | Compose `toEvidence(redact(...).findings)` into detector evidence in `pipeline.ts` next to `injectionEvidence`. |

Things checked and found sound (no row): allowlists and read-only env for both MCP servers; timeouts on every MCP call and REST call; `.env*` never fetched except `.env.example`; lockfiles never model-bound; `assertNoSecretsInPrompt` before every model call and before every debug dump; `oneLine` on every repo-derived fact in the prompt; line-number prefixes make section headers unforgeable from content; `checkModelOutput` fails the run on `unknown_file`; error copy only from `ERROR_COPY`; log() strips Authorization and asserts no secrets; analysis ids are UUIDs; answers body capped; React renders all model text as text (no `dangerouslySetInnerHTML`, no data-driven `href`).
